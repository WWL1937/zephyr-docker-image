# What is this

This is a Docker image based on Ubuntu 24.04 with a complete [Zephyr RTOS](https://zephyrproject.org/) development environment pre-installed, including the west build tool, a Zephyr SDK toolchain, and all required dependencies. The images are automatically built and published to GitHub Releases whenever a new Zephyr version is released, so you always have an up-to-date environment ready to use.

Three variants are built, each with its own `Dockerfile` and workflow, differing only in the Zephyr SDK toolchain installed:

| Variant | Dockerfile           | Workflow                                | Toolchain                          | Release tag           |
| ------- | -------------------- | ---------------------------------------- | ----------------------------------- | ---------------------- |
| ARM     | `Dockerfile.arm`     | `.github/workflows/build-arm.yml`       | `arm-zephyr-eabi`                  | `<version>-arm`            |
| Xtensa ESP32 | `Dockerfile.xtensa-esp32` | `.github/workflows/build-xtensa-esp32.yml` | `xtensa-espressif_esp32_zephyr-elf` | `<version>-xtensa-esp32` |
| RISC-V  | `Dockerfile.riscv`   | `.github/workflows/build-riscv.yml`     | `riscv64-zephyr-elf`               | `<version>-riscv`      |

What's Included

| Component      | Details                                     |
| -------------- | ------------------------------------------- |
| Base OS        | Ubuntu 24.04                                |
| Zephyr SDK     | See toolchain table above                   |
| Build tools    | cmake, ninja, gperf, ccache, make, gcc, g++ |
| Python         | python3 + venv + west                       |
| Device support | dfu-util, device-tree-compiler              |
| SSH server     | openssh-server (port 22)                    |
| Utilities      | git, vim, tree, net-tools, curl, iputils-ping, unzip |

## Gitee Go pipelines

The `.workflow/build-arm.yml`, `.workflow/build-xtensa-esp32.yml` and
`.workflow/build-riscv.yml` pipelines are manual alternatives to GitHub Actions.
Each runs entirely on Gitee cloud resources: resolve the Zephyr version, pass a
version-pinned Dockerfile to the native image-build plugin, push an intermediate
image, then use Skopeo to export it without a Docker daemon and upload it to a
Gitee Release. Existing GitHub workflows are unchanged.
Preparation and publication commands are embedded in each YAML file; no external
`ci` scripts are required. Commands explicitly enter `$WORKSPACE` before execution.

Enable Gitee Go on the Gitee copy of this repository and import the three YAML
pipelines. Add a Docker Registry credential in Gitee Go and configure these
pipeline/global parameters:

| Parameter | Value |
| --------- | ----- |
| `REGISTRY_CERTIFICATE` | ID of the Docker Registry credential used by the native build plugin |
| `REGISTRY_HOST` | The same registry hostname, without a scheme, e.g. `docker.io` |
| `IMAGE_NAMESPACE` | Registry namespace/project, e.g. `my-account` |
| `REGISTRY_USERNAME` | Registry login with read access for Skopeo |
| `REGISTRY_PASSWORD` | Registry password/token; configure as a secret |
| `RELEASE_REPOSITORY` | Target Gitee repository in `owner/repo` form; it must contain the pipeline commit |
| `RELEASE_TOKEN` | Gitee personal access token with repository release/attachment write access; configure as a secret |
| `ZEPHYR_VERSION` | Optional Zephyr tag, e.g. `v4.4.2`; empty resolves the latest GitHub release |

`RESOLVED_VERSION` is generated by the preparation stage through `GITEE_PARAMS`;
do not set it manually. The native build credential must have push access, and
its registry must match `REGISTRY_HOST`. Intermediate images are named
`<registry>/<namespace>/zephyr-sdk-<variant>:<version>`; remove them through your
registry's retention policy when no longer needed.

Select an architecture and start its pipeline manually. Release tags use
`<version>-<variant>`, matching GitHub. Unlike GitHub's 1 GB parts, Gitee uploads
use 95 MiB parts with four-digit suffixes and a `SHA256SUMS` file. Download all
parts, verify them with `sha256sum -c SHA256SUMS`, then concatenate and import as
shown below. A release stays marked as a prerelease until every upload succeeds.
An existing tag/release is not overwritten; delete an incomplete release before
retrying publication. Do not run the same architecture/version concurrently.

**Capacity requirements:** [Gitee's documented limits](https://help.gitee.com/repository/release/create)
are 100 MB per attachment and 1 GB total attachments per ordinary repository
(higher tiers have different quotas). These development images can exceed the
total quota even when split: confirm sufficient repository capacity before
running all three builds. Splitting does not bypass total quotas. Cloud workers
also need sufficient disk/time quotas and access to GitHub, Ubuntu/Python package
sources and your registry. The export task uses the Ubuntu-based GCC cloud
environment with `sudo apt-get` to install Skopeo. If these capabilities are
unavailable in your Gitee plan, the pipeline fails rather than silently skipping
publication.

# Quick Start

## Import from GitHub Release

Each release contains the Docker image split into multiple 1 GB parts (artifact name depends on the variant, e.g. `zephyr-sdk-arm.tar.gz.part*`, `zephyr-sdk-xtensa-esp32.tar.gz.part*`, `zephyr-sdk-riscv.tar.gz.part*`). Download **all** parts for your chosen variant from the [Releases](../../releases) page into the same directory, then follow the steps below.

Linux / macOS

```bash
# Merge parts into a single archive (example: ARM variant)
cat zephyr-sdk-arm.tar.gz.part* > zephyr-sdk-arm.tar.gz

# Import into Docker
docker load < zephyr-sdk-arm.tar.gz
```

## Start container

docker-compose.yml

```yaml
services:
  wwl:
    image: zephyr-sdk-arm:<version>     # replace with the actual version tag, e.g. zephyr-sdk-arm:v4.4.2
    container_name: wwl
    environment:
      USER_PASSWORD: wwl
    ports:
      - "10022:22"
      - "11234:1234"
    volumes:
      - /home/wwl/note:/workspace
      - /dev:/dev
    restart: unless-stopped
```

> Replace `<version>` with the tag shown after `docker images`, e.g. `zephyr-sdk-arm:v4.4.2`.

Start the container:

```bash
docker compose up -d
```

Connect via SSH:

```bash
ssh -p 10022 user@localhost
# password: whatever you set in USER_PASSWORD
```

Stop the container:

```bash
docker compose down
```
